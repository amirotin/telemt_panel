# Запуск, остановка и перезапуск Telemt

В **Сервер → Платформа** доступны команды для службы или контейнера Telemt:
«Запустить», «Остановить» и «Перезапустить». Каждая команда требует подтверждения.
Остановка разрывает подключения клиентов; запуск и остановка не меняют автозапуск.

## Какую службу контролирует панель

Это управление **на хосте панели**, через выбранный `[host] service_manager`.
Используется `telemt_service`, а для Docker — `telemt_container`.
Имя службы/контейнера и менеджер показаны перед кнопками и в подтверждении.
Поддерживаются systemd, OpenRC, procd, SysVinit и Docker при наличии доступа.
Для других установок предусмотрены [пользовательские команды](CONFIG.md#hostcommands--пользовательские-команды):
три действия Telemt и отдельный перезапуск панели, заданные только в конфиге.

Адрес `[telemt] url` не задаёт цель системной команды. Например, SSH-туннель
к удалённому API не превращает локальный `systemctl` в управление удалённым
сервером. В таком случае используйте ручное управление на нужном сервере.
Панель не подключает Docker socket и не настраивает SSH самостоятельно.

Совпадающие привязки Telemt и самой панели блокируют запуск/остановку Telemt.
Укажите разные службы; команды для произвольных имён через API не принимаются.

## Состояние и результат команды

Состояние «Работает» / «Остановлен» приходит от менеджера служб, независимо от
доступности API Telemt. Если состояние нельзя надёжно получить (в частности,
SysVinit), показано «Статус неизвестен». При наличии прав доступны обе команды,
с дополнительным предупреждением. Ошибка чтения статуса не означает остановку.

Для systemd панель также различает «Сбой» и штатную остановку; при сбое доступен
переход к журналу Telemt. «Запускается», «Останавливается» и «Перечитывает
конфигурацию» передают наблюдаемое состояние, без вывода о причине или цикле
перезапусков. API сохраняет `status: running|stopped|unknown` и дополнительно
возвращает `native_state`, если менеджер поддерживает детализацию. Один запрос
состояния выполняет одну системную команду.

Фоновая проверка состояния после успешной загрузки не блокирует действия и их
подтверждение. Начальная загрузка, ошибка чтения, выполнение команды и занятая
общая блокировка по-прежнему блокируют команды.

Успех команды не гарантирует, что API уже готов к работе. Панель перечитывает
состояние после команды и обновляет его, пока открыта страница. Если выполнение
оборвалось или истекло время ожидания, результат отмечается как неподтверждённый:
проверьте службу перед повторением. API возвращает HTTP 502 с кодом
`service_action_unconfirmed`, в том числе для перезапуска. Автоматического повтора нет.

Запуск, остановка, перезапуск и установка обновлений используют общую блокировку:
две такие операции одновременно не выполняются. Действия попадают в аудит, если
его хранение включено.

## Права после обновления панели

В режиме `direct` команды выполняются с правами процесса панели. В режиме `sudo`
нужны точные разрешения на соответствующую команду. Новая установка через
инсталлятор добавляет запуск и остановку **только Telemt**, не самой панели.

Обновление бинарника **не переписывает существующие sudoers**. Старые разрешения
на перезапуск и обновления продолжают работать; отсутствие новых прав ограничивает
только запуск/остановку. Вместо выполнения панель показывает ручную команду.

Например, для systemd, пользователя `telemt-panel` и службы `telemt` администратор
может добавить через `visudo` два правила, сохранив остальные:

```sudoers
telemt-panel ALL=(root) NOPASSWD: /usr/bin/systemctl start telemt
telemt-panel ALL=(root) NOPASSWD: /usr/bin/systemctl stop telemt
```

Это пример: проверьте путь `command -v systemctl`, пользователя процесса и точное
имя из `[host] telemt_service`. Для другой init-системы аргументы отличаются.
Не выдавайте `NOPASSWD: ALL` и не используйте wildcard вместо имени службы.
После изменения правил перезапустите **панель**, чтобы она повторно проверила права.

В режиме `manual` команды из интерфейса не выполняются: используйте показанную
инструкцию с необходимыми правами на нужном хосте.
