# Восстановление доступа к панели

Пароль администратора задаётся только в `auth.password_hash` конфигурации
панели. Для его сброса нужен доступ к серверу и право редактировать этот файл.
Панель не предоставляет публичный HTTP-endpoint для восстановления пароля.

1. Остановите **панель**, не Telemt. Используйте тот же способ управления,
   которым её запускали: например, `sudo systemctl stop telemt-panel` для
   systemd или `/etc/init.d/telemt-panel stop` для procd/sysvinit. В Docker
   остановите контейнер панели; конфиг редактируется в подключённом томе.
2. Запустите `telemt-panel hash-password` в терминале. Введите и подтвердите новый пароль:
   ввод скрыт, на экран выводится только bcrypt-хеш. Не передавайте пароль
   аргументом команды и не записывайте его открытым текстом в конфиг.
   Для Docker команду можно запустить в отдельном временном контейнере
   из того же образа с интерактивным терминалом.
3. В конфиге **панели** замените только значение `password_hash` в `[auth]`
   на полученный хеш, заключённый в кавычки. Обычно это
   `/etc/telemt-panel/config.toml`; при запуске с `--config` используйте
   фактически указанный файл. Логин остаётся в `auth.username`.
   Сохраните владельца и закрытые права файла (обычно `0600`), чтобы
   пользователь сервиса мог его прочитать. Не редактируйте конфиг Telemt.
4. Запустите панель и войдите с новым паролем. Старый пароль больше не
   подходит; все прежние сессии, включая созданные через passkey, отозваны.

Passkeys не удаляются: ими можно войти заново. Если ключ потерян или
скомпрометирован, после входа удалите его в настройках безопасности панели.
Смена пароля не заменяет отзыв такого ключа.

Доступны два способа входа: пароль и необязательные passkeys. Парольный вход
остаётся доступным независимо от наличия passkeys.

Не удаляйте `panel-state.json` или базу истории ради сброса пароля: настройки,
подписки, passkeys и статистика должны сохраниться. Сброс не требует SQLite
и работает также с memory/lite. При `data_dir = ""` сессии и так исчезают
после остановки процесса.

Обычный перезапуск с неизменными `auth.username` и `auth.password_hash`
сохраняет действующие сессии.
Изменение логина или даже повторное хеширование того же пароля завершает их.
Если сохранить отзыв в файл состояния не удалось, панель не запускает HTTP-
сервер: исправьте права или доступность диска и повторите запуск.
