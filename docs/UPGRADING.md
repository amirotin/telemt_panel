# Обновление существующей установки

Повторный запуск `install.sh` с существующим конфигом обновляет **только бинарник**.
Конфиг, сервисный пользователь, unit/init-скрипт, sudoers и правила firewall
сохраняются. Для изменения этих параметров нужна отдельная настройка; переменные
первичной установки не переопределяют работающий сервис при обновлении.

## Порядок

1. Скрипт читает защищённую копию конфига, получает новый бинарник и проверяет
   checksum и структуру архива. Явный `--binary` означает доверенный локальный файл.
2. Новый бинарник разбирает TOML. Проверяются пути, имя сервиса, профиль full/lite;
   версия скачанного бинарника должна соответствовать тегу релиза.
3. После подтверждения скрипт проверяет текущий HTTP/HTTPS-ответ и сохраняет
   резервный бинарник в закрытом каталоге рядом с установленным:
   `.telemt-panel-backup.XXXXXX/binary`.
4. Сервис останавливается, новый файл устанавливается атомарным переименованием,
   сервис перезапускается. Проверяется health с **точной версией**, включая TLS/SNI;
   один HTTP 200 не считается подтверждением запуска новой панели.
5. Если замена, restart или проверка не удались, восстанавливается резервный
   бинарник и проверяется прежний ответ панели. Для systemd сбрасывается failed-
   состояние только этого сервиса, чтобы StartLimit не блокировал восстановление.

Backup остаётся после успеха и после отказа. Его путь указан в выводе. При
неуспешном автоматическом восстановлении скрипт завершится с ошибкой и попросит
восстановить этот файл и перезапустить сервис вручную. Даже успешный откат не
превращает неудачное обновление в успешный exit 0.

Сохраняются владелец, группа и режим резервного файла. GNU cp также сохраняет
расширенные атрибуты/ACL; возможности BusyBox ограничены его реализацией cp.
Это восстановление бинарника, а не резервная копия БД, state или всей системы.
Произвольная несовместимость форматов данных между версиями этим не исправляется.

## Особенности

- `--dry-run` выполняет загрузку/проверку во временном каталоге, но не заменяет
  бинарник и не перезапускает сервис. Содержимое записываемых файлов не печатается.
- `--no-start` оставляет backup и новый бинарник без проверки запуска. Работающий
  старый процесс продолжает использовать прежний образ до ручного restart.
- Для проверки нужны `timeout`, `sha256sum`, `readlink` и исполняемый временный
  каталог. При `noexec` на `/tmp` выберите его явно, например
  `TMPDIR=/var/tmp sh install.sh`. Скрипт не меняет mount-политику системы.
- `--variant` задаёт профиль явно. Для локального `--binary` без `--variant`
  профиль берётся из проверяемого бинарника; lite с SQLite-конфигом отклоняется.
- Конфиг 0.6 читается тем же Go-декодером, что при запуске, и остаётся побайтно
  прежним. Одноразовый перенос состояния выполняется при старте: check/off,
  интервал 6 часов, без автоустановки. JWT требует нового входа.
- Установщик должен запускаться при отсутствии другой операции обновления.
  Механизм не обещает восстановление при аварии питания или принудительном SIGKILL.

Самообновление из веб-интерфейса 0.6.2 — другой путь: старый процесс может быть
остановлен systemd раньше проверки результата, поэтому при падении нового
бинарника **автоматического отката 0.6.2 нет**. Сохранённый им `done` не доказывает
успех. Для контролируемого перехода используйте актуальный установщик.
