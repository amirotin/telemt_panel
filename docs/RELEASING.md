# Подготовка релиза 1.x

## Проверки до публикации

- `CI` на push/PR выполняет full/lite tests, lint, обязательный Staticcheck,
  проверку reachable Go advisories, frontend-тесты, TypeScript, SDK drift и
  сборку. Deadcode/Knip сохраняют отчёты для review с test/plugin entries;
  generated SDK и route tree проверяются своим pipeline. Prettier остаётся
  необязательным. E2E использует проверенный бинарник из этого же запуска.
- `Race` выполняет full/lite tests с CGO раз в неделю (воскресенье,
  03:23 UTC) и вручную через Actions → Race → Run workflow. Локальный запуск
  требует C-компилятор: `CGO_ENABLED=1 make test-race`.
- `Release contract` отдельно собирает все архитектуры/профили и проверяет
  архивы при изменении Go/веб-кода, зависимостей, сборочных скриптов, API или
  workflows; можно запустить вручную. Проверки не создают релиз.
  На время отдельного исследования размера integration workflow явно использует
  `RELEASE_CHECK_SIZE=0`: размер измеряется, а остальные проверки выполняются
  полностью. Отдельный advisory шаг показывает бюджеты всех четырёх бинарников.
  Это не разрешение публикации: обычный `make release` и workflow `Release`
  сохраняют строгие лимиты 32/16 МиБ.
- `Release` для тега **обязательно вызывает полный Race** перед сборкой и
  публикацией. Успешный старый недельный прогон не заменяет проверку кода тега.

Новые push отменяют устаревшие запуски соответствующего CI/контрактного workflow
для той же ветки или PR. Если включаете обязательные status checks в защите ветки,
учитывайте фильтры путей: пропущенный workflow не создаёт успешный check.

## Локальная сборка без публикации

Используйте Go из `go.mod` и Node.js 22. Для локальной разработки запускайте
сборку в отдельной копии исходников: `make release` создаёт `release/` и frontend
артефакты. Они не должны попадать в Git.

```sh
make release VERSION=1.0.0-rc.audit
RELEASE_DIR="$PWD/release" RELEASE_VERSION=1.0.0-rc.audit \
  go test -count=1 -run '^TestReleaseContract$' ./internal/update/
```

Команды не создают тег и не публикуют релиз. `make release` очищает свой
disposable `release/` перед сборкой; сохраните нужные старые результаты в
отдельном каталоге. Контракт отвергает лишние файлы и каталоги.

Все проверки должны относиться к одному снимку исходников и свежим артефактам.
Перед выпуском повторите full/lite tests и vet, CGO race, frontend tests/lint/
typecheck/build, SDK drift, Staticcheck и dependency scanners. Для lite задавайте
`GOEXPERIMENT=nojsonv2` и `-tags lite`, как в CI. Браузерная проверка включает
сохранение черновиков при задержанных ответах, proxy/base_path, RU/EN, 320/390 px,
reduced motion, 2000 пользователей и бюджет загрузки assets.

Отдельно нужны установка, native update/rollback и восстановление прав с
предыдущего поддержанного профиля, Docker nonroot/mounts и обе архитектуры.
Контейнер или эмуляция размеров экрана не подтверждают физический телефон,
ARM-хост и реальный service manager. Записывайте непроверенные сценарии явно.
До публикации обновите README, Compose, DOCKER и примеры workflow согласованным
проверенным тегом; локальное имя `rc.audit` не является опубликованным релизом.

## Переходная матрица 0.6.2 → 1.0

| Профиль | Архитектуры | Драйверы истории | Лимит бинарника |
| --- | --- | --- | --- |
| full | x86_64, aarch64 | memory, sqlite | 32 МиБ |
| lite | x86_64, aarch64 | memory | 16 МиБ |

Архитектуры соответствуют официальным сборкам Telemt: x86_64 и aarch64.
ARMv7, MIPS и другие 32-битные цели не выпускаются. Вариант Telemt x86_64-v3 —
CPU-оптимизация, не отдельная архитектура панели: наша сборка x86_64 использует
`GOAMD64=v1` и работает также на v3-совместимых процессорах.

Все бинарники статические, `CGO_ENABLED=0`, с `-trimpath`.
Только lite использует документированный Go 1.27 opt-out
`GOEXPERIMENT=nojsonv2`, чтобы сохранить размер ≤16 МиБ. API `encoding/json`
и возможности панели сохраняются; full использует default json/v2, требуемый
SQLite. Lite tests, race, Staticcheck и scanner используют тот же opt-out.
Он временный: при обновлении Go заново проверьте четыре размера и users-poll
p95 на том же оборудовании (допустимая регрессия ≤10%). Если Go удалит opt-out,
сначала найдите совместимую оптимизацию, затем обновляйте toolchain.
Для переходного релиза сохраняются имена с `linux-gnu` и
`linux-musl`: это одинаковые бинарники под совместимыми именами, а не разные libc.

- Full: `telemt-panel-<arch>-linux-<gnu|musl>.tar.gz`.
- Lite: `telemt-panel-lite-<arch>-linux-<gnu|musl>.tar.gz`.

Итого 4 уникальных бинарника, 8 архивов и 8 файлов `<archive>.sha256`.
В каждом архиве — только
`telemt-panel`, обычный файл с mode 0755 и UID/GID 0. Старый updater 0.6.2
поддерживает x86_64/aarch64 и выбирает full; нужные ему имена сохранены.
MIT и third-party notices встроены в SPA как `licenses/*.txt`; tar-формат
с единственным бинарником сохраняется.

Контракт проверяет весь набор, суммы, архивы/CRC, ELF-архитектуру и endian,
статическую сборку, профили, лимиты и идентичность aliases. Он использует настоящий
extractor updater. Для native-архитектуры выполняет `version`; для остальных
проверяет ELF/build metadata и наличие строки версии, не эмулирует запуск.
В build metadata с `-trimpath` нет `-ldflags`, поэтому версия не читается из них.

`RELEASE_CHECK_SIZE=0` допустим только для квалификации без публикации, когда
размер явно исследуется отдельно. Он не отменяет safety bound чтения архива,
CRC, ELF, checksums, версию или состав профиля. `TestReleaseBinarySizeBudgets`
всегда проверяет исходные лимиты, независимо от этого переключателя. После
исследования integration workflow нужно вернуть к строгому режиму.

## Публикация

Workflow `release.yml` запускается при push тега `v1.*`. Он проверяет формат тега,
собирает архивы и запускает контракт **до** `gh release create`. Релиз сначала
создаётся как draft; публикация выполняется только после успешной загрузки всех
assets. Ошибка загрузки оставляет draft для ручной проверки, а не публичный
неполный релиз. Тег с prerelease
частью (например `v1.0.0-rc.1`) создаёт prerelease. Дефис только в build metadata
не меняет статус стабильного релиза.

Создание/push тега — отдельное осознанное действие после проверок перехода и
восстановления. Локальные тесты и actionlint не подтверждают разрешения токена,
доступность GitHub или успешную загрузку assets: это проверяется настоящим
публикационным прогоном отдельно. Лимиты full/lite не повышайте молча при ошибке
сборки; сначала выясните причину изменения размера.
