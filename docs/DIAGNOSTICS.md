# Ошибки API Telemt

Панель различает отказ соединения с API, ошибку полученного ответа и отказ операции на стороне Telemt. Работающий прокси может отдавать статистику, но не иметь возможности сохранить конфигурацию при создании пользователя.

Для ошибок API уведомление может содержать безопасные сведения, например `HTTP 500 · internal_error · #42`. Последняя часть — номер запроса Telemt, если сервис его передал. Эти сведения помогают сопоставить операцию с журналом. Произвольные ответы сервиса, пароли, секреты и адреса с учётными данными не добавляются в уведомление.

| Код | Причина | Что проверить |
| --- | --- | --- |
| `telemt_config_permission_denied` | Telemt сообщил об отказе прав при чтении или записи конфигурации | Владельца конфигурации и её lock-файла, пользователя службы Telemt и права каталога |
| `telemt_config_read_only` | Файловая система конфигурации доступна только для чтения | Режим монтирования каталога, включая Docker volumes |
| `telemt_config_storage_full` | Не хватает места или исчерпана дисковая квота | Свободное место и квоты файловой системы конфигурации |
| `telemt_config_write_failed` | Другая ошибка сохранения конфигурации | Каталог, монтирование и журнал Telemt; при Docker монтировать каталог, а не один файл |
| `telemt_config_read_failed` | Не удалось прочитать конфигурацию | Основной файл, include-файлы и доступ к ним от имени службы Telemt |
| `telemt_auth_failed` | API Telemt отклонил авторизацию панели | Точное значение `auth_header`; это не истечение сессии администратора панели |
| `telemt_timeout` | Истёк срок ожидания ответа или API вернул HTTP 504 | Нагрузку, журнал и доступность API; после изменения сначала проверить его результат |
| `telemt_dns_failed` | Сервер панели не смог определить IP-адрес API | Адрес API и DNS на сервере панели |
| `telemt_tls_failed` | Не удалось проверить сертификат API | Имя сервера, срок действия сертификата и цепочку доверия |
| `telemt_invalid_response` | Ответ повреждён, обрезан или не соответствует ожидаемому формату | Адрес API, обратный прокси и совместимость версий |
| `telemt_api_error` | Telemt или промежуточный сервер вернул другую ошибку API | HTTP-статус, код и номер запроса из уведомления, журнал Telemt |
| `telemt_unreachable` | Не удалось установить соединение; более точная причина не определена | Адрес, порт API, listener Telemt и сетевую доступность с сервера панели |
| `snapshot_unavailable` | Для выбранной темы ещё не опубликованы данные | Дождаться публикации и повторить загрузку; это само по себе не означает сбой Telemt |

Если только ошибка прав мешает добавлению пользователя, менять sudoers панели не требуется: конфигурацию сохраняет процесс Telemt через его API. Для стандартного пути метаданные можно проверить без вывода секретов:

```sh
stat -c '%U:%G %a %n' /etc/telemt /etc/telemt/telemt.toml
systemctl show telemt -p User -p Group
```

Telemt сохраняет файл атомарно: нужны права на создание временного файла и lock-файла в каталоге. Если его версия также сохраняет владельца через `fchown`, пользователь службы должен иметь возможность назначить владельца исходного файла временному. Например, сочетание службы `telemt` и конфига `root:telemt 0640` может позволять чтение, но блокировать сохранение.

После таймаута или неподтверждённой записи не следует сразу повторять изменение. Проверьте список пользователей либо текущую конфигурацию: операция могла завершиться после обрыва ответа. Для редактора конфигурации остаётся отдельная ошибка `telemt_config_outcome_unknown` с сохранением черновика и проверкой результата записи.
