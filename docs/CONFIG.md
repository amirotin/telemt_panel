# Конфигурация хранилища

Обычная сборка `telemt-panel` включает memory и SQLite. `telemt-panel-lite` предназначена для роутеров и включает только memory. Текущий вариант и список драйверов показывает `telemt-panel version` и `GET /api/health`.

## SQLite

Рекомендуемый вариант для одной панели на сервере:

```toml
[store]
driver = "sqlite"
path = "/var/lib/telemt-panel/panel.db"
```

## Что хранится

История состояния и метрик опциональна. Технические метрики, события, проблемы подключений, общий трафик и расширенная диагностика имеют отдельные карточки с переключателем и собственным сроком хранения. Живые графики продолжают работать в RAM при отключённой записи. Ранее сохранённые параметры отображаются без объединения категорий или изменения выбранных сроков.

Трафик пользователей, история IP и аудит имеют независимые настройки в разделе «Сервер → Настройки панели → История и хранение». История адресов (`user_ip_history`) собирается постоянно; администратор выбирает срок и может очистить накопленное. Учёт накопительного трафика пользователей ведётся всегда: переключатель `user_traffic` отключает только временные корзины и графики, но не итоги и baseline.

Уменьшение любого срока требует подтверждения перед сохранением, в том числе через API (`confirm_retention_reduction: true`). Изменение выбора или отмена подтверждения ничего не удаляет. Сначала сохраняется локальное состояние, затем правила применяются к истории: ошибка записи state-файла не меняет retention активного хранилища.

История трафика пользователя сохраняет только объём за интервал: без IP-адресов, маршрутов и сырых снимков пользователя. Нулевые интервалы не записываются. За последние 24 часа используются 15-минутные корзины, более старая часть выбранного периода представлена часовыми корзинами, а долгосрочная часть — дневными. Обычное удаление пользователя не удаляет его учёт: очистка графиков и полный сброс итога доступны как разные подтверждаемые действия.

Лента событий хранит структурированные переходы состояния и безопасные административные действия для сопоставления с графиками. В неё не копируются сырые логи, адреса клиентов, секреты, полные конфиги и данные входа администратора. API явно различает отключённую историю, пустой период, частичную ретенцию и временно недоступный источник — пустой график не выдаётся за нулевую активность.

## Детализация истории состояния

Живые числовые ряды хранятся в RAM до двух часов, независимо от включения
дисковой категории. Ограничение числа точек может сократить окно при опросе
чаще пяти секунд. Этот буфер исчезает при перезапуске панели.

SQLite больше не записывает каждый замер отдельной строкой: раз в пять минут
панель пакетно сохраняет пятиминутные и часовые агрегаты. Пятиминутная
детализация хранится до семи дней, часовая — в пределах срока соответствующей
категории. Штатное закрытие и экспорт также сохраняют накопленный пакет.
При аварийном завершении возможна потеря последнего несохранённого интервала;
после ошибки записи пакет остаётся в ограниченном RAM-буфере для повторной попытки.
Эти правила не изменяют запись событий, учёт трафика пользователей и историю IP.

Для показателей сохраняются среднее, минимум, максимум и число замеров.
Накопительные счётчики не усредняются: сохраняются последнее значение,
границы наблюдений, наблюдаемое приращение и разрывы. Приращение не включает
неизвестное движение внутри пропуска и не является точным объёмом за весь
номинальный интервал. Сброс счётчика не превращается в отрицательный трафик.

Старые raw / минутные / пятнадцатиминутные записи остаются читаемыми после
миграции, без дублирования разрешений. Неизвестные минимумы старых агрегатов
не восстанавливаются из средних. Экспорт формата 7 сохраняет новые метаданные;
импорт прежних форматов поддерживается.

API истории поддерживает диапазоны до 90 дней. Большие ответы укрупняются
до часовых агрегатов с сохранением экстремумов. Текущие KPI по-прежнему
используют два пятнадцатиминутных окна.

В настройках отображаются общий размер SQLite и количество записей по категориям.
Размер отдельных таблиц не рассчитывается: для этой панели он не оправдывает
усложнение драйвера. Общий размер базы включает разные виды истории, а не только
метрики и события. В режиме RAM размер на диске равен нулю.

## История IP-адресов

Панель объединяет активные адреса и адреса недавнего окна из `GET /v1/users`.
Используется существующий периодический опрос (обычно 10 секунд), без отдельного
запроса на каждого пользователя. Размер недавнего окна берётся из effective limits
Telemt; при недоступности источника он неизвестен, а не автоматически равен 30 секундам.

Сохраняются канонический IPv4/IPv6, первое и последнее время наблюдения панелью,
число наблюдений и последний источник. IPv4-mapped IPv6 объединяются с IPv4.
Пакеты, маршруты и трафик по IP не сохраняются. Время наблюдения не равно времени
начала/завершения сессии; короткие подключения между опросами могут быть пропущены.
Смена адреса сама по себе не доказывает передачу доступа другому человеку.

- SQLite: по умолчанию 30 дней, до 256 адресов на пользователя и 100 000 на панель.
- Memory: до 24 часов, до 256 адресов на пользователя и 20 000 на панель; после
  перезапуска история исчезает. Выбранная политика не увеличивает этот предел.
- SQLite записывается пакетами примерно раз в минуту; первая запись — сразу.
  Незавершённый пакет сохраняется при штатном завершении. При аварии возможна
  потеря последней минуты; при ошибке записи пакет ограничен по размеру и повторяется.
- При достижении лимита старые записи вытесняются, API сообщает `history_limited`.
  Уменьшение срока сразу ограничивает выдачу. Физическая очистка идёт при записи
  и не реже примерно раза в час через фоновый опрос, даже при недоступном Telemt.
  Просроченные адреса исключаются из экспорта независимо от этого опроса.
- История не попадает в `panel-state.json`. Экспорт формата 6 включает IP вместе с
  остальной историей; импорт формата 5 добавляет новую политику без сброса старых.

API: `GET /api/users/{username}/ip-history` с `range=24h|7d|30d|all`,
`family=all|4|6`, буквальным поиском `q`, `limit=1..200` и `cursor`.
Все периоды заканчиваются сейчас; это не посуточная статистика уникальных IP.
История читается и при недоступном Telemt. `active_now=null` означает неизвестное
текущее состояние, в том числе наблюдение старше 30 секунд.

`POST /api/users/{username}/ip-history/reset` с `{"confirm":true}` очищает историю
одной учётной записи. Общая очистка доступна через категорию `user_ip_history`.
Она не сбрасывает трафик и не меняет настройки Telemt. Следующий периодический
опрос может обнаружить адреса снова. Обычное удаление пользователя историю не
удаляет; новое использование того же имени продолжает историю этой учётной записи.

## География IP (GeoIP)

Раздел «Сервер → Настройки панели → География IP» подключает локальные базы MMDB
для истории адресов в карточке пользователя. По умолчанию GeoIP выключен:
никакие базы не скачиваются, пока администратор не нажмёт «Подключить базы».

Три источника:

- **P3TERX** — готовые GeoLite2 из [P3TERX/GeoLite.mmdb](https://github.com/P3TERX/GeoLite.mmdb).
  Это сторонняя публикация данных MaxMind, не официальный сервис панели.
  Авторство и условия использования приведены в репозитории источника.
- **Свои ссылки** — прямые HTTPS-адреса отдельных `.mmdb`. Архивы,
  авторизация провайдера и загрузки с локальных/служебных сетевых адресов
  не поддерживаются. Query-параметры ссылок сохраняются как часть настроек;
  не публикуйте резервные копии state-файла.
- **Файлы на диске** — абсолютные пути на сервере панели. Исходные обычные
  файлы должны быть доступны пользователю панели для чтения; они не изменяются.
  После внешней замены файлов нажмите «Перечитать файлы».

Обычно достаточно Country и ASN. City добавляет приблизительный город,
а не достоверное местоположение человека. Поддерживаются IPv4 и IPv6.
Для частных/служебных адресов и отсутствующих записей показываются отдельные
состояния; это не признак проблемы Telemt.

Настройки сохраняются в `panel-state.json`, управляемые копии баз — в
`data_dir/geoip`. Для GeoIP нужен заданный `data_dir` с доступом на запись.
Если это временный каталог OpenWrt, базы исчезнут после перезагрузки;
Country/ASN предпочтительнее более крупной City на малом устройстве.
Загрузка ограничена 128 MiB на файл и 120 секундами, только HTTPS.
Предыдущий исправный набор остаётся активным при ошибке загрузки/проверки.
Переключение набора происходит целиком; при обновлении страна и ASN не берутся
из разных поколений одного набора. Дата данных берётся из метаданных MMDB.

Для сетевых источников можно выбрать ежедневную/еженедельную проверку либо
только ручное обновление. Локальные файлы перечитываются явно. Отключение GeoIP
не удаляет историю IP и не меняет конфигурацию Telemt.

IP сопоставляются с базами только при чтении текущей страницы истории.
География не копируется в SQLite и не отправляется внешним сервисам;
ошибка или отсутствие баз не мешает сбору адресов. Экспорт хранилища переносит
настройки источника, но не сами MMDB: на другом сервере перепроверьте пути
и подключите базы заново.

API: `GET/PUT /api/settings/geoip`, `POST /api/settings/geoip/update`.
Применение асинхронное (`202`), его состояние доступно в GET.
История IP возвращает общий `geoip`-статус и `geo` в каждой строке
(`null`, если активных баз нет).

## Memory

```toml
[store]
driver = "memory"
```

Этот режим подходит OpenWrt и временным установкам. История остаётся в RAM. Обязательное состояние панели всегда отделено от истории и при заданном `data_dir` сохраняется в `data_dir/panel-state.json`: сессии, настройки, политики, TOTP/passkeys, nonce, аудит и recovery-журнал обновлений.

Живые метрики используют ограниченный двухчасовой буфер RAM в обоих режимах хранения. Отключение записи категории метрик на диск не выключает живые графики. При более частом опросе лимит точек может сократить доступный интервал; пропуски наблюдения не заполняются нулями. После перезапуска панели буфер накапливается заново, а ранее сохраненная дисковая история остается доступной по действующей политике.

## Резервная копия и перенос истории

Остановите панель, выгрузите состояние из текущего драйвера, затем укажите в отдельной копии конфига новый драйвер и пустую базу:

```sh
telemt-panel store export --config /etc/telemt-panel/config.toml --out panel-store.json
telemt-panel store import --config /etc/telemt-panel/config-new.toml --in panel-store.json
```

Экспорт объединяет локальное состояние панели и историю выбранного драйвера в один переносимый файл, но сохраняет их как независимые части. Он включает сессии, настройки, nonce, recovery-журнал, политики, ограниченный аудит, auth-состояние, метрики, события и учёт трафика с baseline и временными корзинами; незавершённые WebAuthn-операции и параметры конфига не экспортируются. Файл содержит чувствительные данные авторизации, создаётся с правами `0600`, а существующий файл команда не перезаписывает. При импорте state-часть возвращается в `panel-state.json`, а историческая часть — в пустое хранилище истории.

## Переключение варианта бинаря

Вариант меняется только установщиком, без перезаписи существующего конфига:

```sh
sh install.sh --variant full
sh install.sh --variant lite
```

Lite не может открыть SQLite. При обновлении существующей установки установщик проверяет сохранённый конфиг до замены бинарника и откажется переключать такой профиль на lite. Для осознанного перехода сначала перенесите нужное состояние и смените драйвер на memory.
