# Конфигурация панели

Панель читает TOML-файл при запуске и не перезаписывает его. После правок
перезапустите панель. Это конфигурация самой панели, не сервиса Telemt.

Полный пример: [`config.example.toml`](../config.example.toml).
По умолчанию читается `config.toml` из текущего каталога; установщик использует
`/etc/telemt-panel/config.toml`. Другой путь задаётся явно:

```sh
telemt-panel --config /etc/telemt-panel/config.toml
```

Ниже указаны значения загрузчика по умолчанию. Установщик может явно задать
другие значения в созданном файле, например выбрать SQLite вместо memory.

## Общие параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `listen` | `"0.0.0.0:8080"` | Адрес и порт HTTP-сервера панели. За локальным reverse proxy можно указать `"127.0.0.1:8080"`. |
| `base_path` | `""` | Префикс URL за reverse proxy, например `"/panel"`. |
| `trusted_proxies` | `[]` | Доверенные IP/CIDR reverse proxy. Только от них принимаются `X-Forwarded-For` и `X-Forwarded-Proto`. |
| `data_dir` | `"/var/lib/telemt-panel"` | Каталог состояния панели, временных файлов обновления и управляемых баз GeoIP. Нужен доступ на запись от пользователя панели. |

В `data_dir/panel-state.json` сохраняются настройки, сессии и параметры входа,
независимо от драйвера истории. При `data_dir = ""` это состояние живёт только
до завершения процесса. Каталог в `/tmp` также не переживает перезагрузку системы.
State-файл может содержать секреты; не публикуйте его и резервные копии.

### Reverse proxy

Прокси должен удалять `base_path` перед передачей запроса панели. Для
`base_path = "/panel"` пример nginx:

```nginx
location = /panel { return 301 /panel/; }
location /panel/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_buffering off;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

`base_path` допускает буквы ASCII, цифры и символы `._~/-`, без query-параметров.
Добавляйте в `trusted_proxies` только реальные адреса своего прокси, не весь интернет.

## `[telemt]` — подключение к Telemt

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `url` | Обязателен | Базовый URL API Telemt, например `"http://127.0.0.1:9091"`. |
| `auth_header` | `""` | Полное значение заголовка `Authorization`, совпадающее с `server.api.auth_header` в Telemt. |
| `config_edit_mode` | `"api"` | Редактирование настроек Telemt через Config API. Значение `"file"` принимается конфигом, но прямое редактирование файла пока не реализовано. |

## `[auth]` — вход в панель

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `username` | Обязателен | Логин администратора. В примере — `"admin"`. |
| `password_hash` | Обязателен | Bcrypt-хеш пароля, не пароль открытым текстом. |
| `session_ttl` | `"720h"` | Скользящий срок сессии. Положительная длительность, например `"24h"` или `"720h"`; суффикс `d` не поддерживается. |

Хеш создаётся интерактивно, без пароля в аргументах командной строки:

```sh
telemt-panel hash-password
```

Изменение логина или хеша завершает прежние сессии при следующем запуске.
Порядок сброса пароля: [восстановление доступа](ACCESS_RECOVERY.md).

## `[store]` — хранение истории

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `driver` | `"memory"` | `"sqlite"` — история на диске; `"memory"` — история в RAM, исчезающая при перезапуске. |
| `path` | `""` | Путь к SQLite-файлу. Обязателен для `"sqlite"`, не используется для `"memory"`. |

Для сервера обычно используется:

```toml
[store]
driver = "sqlite"
path = "/var/lib/telemt-panel/panel.db"
```

Обычная сборка поддерживает оба драйвера, lite — только memory. Переключение
драйвера или пути не переносит старую историю автоматически. `data_dir` и
`store.path` независимы: смена каталога состояния не меняет путь базы.

Политики хранения, GeoIP и дополнительные способы входа сохраняются отдельно
в state-файле; TOML-параметров для них нет.

## `[subpage]` — страницы подписки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `enabled` | `false` | Включает страницы `/sub/<token>`, доступные без входа администратора. |
| `secret` | `""` | HMAC-ключ токенов. Обязателен при включении; установщик генерирует его автоматически. |

## `[host]` — сервисы и журналы

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `service_manager` | `"auto"` | `auto`, `systemd`, `openrc`, `procd`, `sysvinit`, `docker` или `none`. |
| `log_source` | `"auto"` | `auto`, `journald`, `logread`, `syslog`, `docker` или `file`. |
| `log_file` | `""` | Путь к журналу при `log_source = "file"`. |
| `telemt_service` | `"telemt"` | Имя службы Telemt. |
| `panel_service` | `"telemt-panel"` | Имя службы панели. |
| `telemt_container` | `"telemt"` | Имя контейнера Telemt при работе через Docker. |
| `panel_container` | `"telemt-panel"` | Имя контейнера панели при работе через Docker. |

`auto` определяет доступные средства при запуске. Имена служб и контейнеров
должны соответствовать установленным на вашем сервере.

## `[privileges]` — права на операции с хостом

`mode = "auto"` выбирает прямое выполнение под root, иначе доступный
неинтерактивный sudo, иначе ручные команды. Можно явно указать `"direct"`,
`"sudo"` или `"manual"`. Выбранный режим используется и для Telemt, и для панели;
сам параметр не выдаёт процессу дополнительных прав.

## `[updates]` — обновления

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `telemt_repo` | `"telemt/telemt"` | GitHub-репозиторий релизов Telemt в формате `owner/name`. |
| `panel_repo` | `"amirotin/telemt_panel"` | GitHub-репозиторий релизов панели. |
| `github_token` | `""` | Необязательный токен GitHub для приватного репозитория или повышения лимита API. |
| `telemt_binary_path` | `"/bin/telemt"` | Установленный бинарник Telemt, заменяемый при обновлении. |
| `panel_binary_path` | `"/usr/local/bin/telemt-panel"` | Установленный бинарник панели, заменяемый при обновлении. |

Пути должны совпадать с фактическими исполняемыми файлами служб.
Конфигурацию с токенами храните с ограниченными правами чтения.
