# Конфигурация панели

Панель читает TOML-файл при запуске и не перезаписывает его. После правок
перезапустите панель. Это конфигурация самой панели, не сервиса Telemt.

Неизвестные ключи и разделы отклоняются при загрузке: в ошибке перечисляются их
пути, без значений. Это помогает заметить опечатку вместо запуска с настройками
по умолчанию. Проверка не распространяется на конфигурацию Telemt.

Полный пример: [`config.example.toml`](../config.example.toml).
По умолчанию читается `config.toml` из текущего каталога; установщик использует
`/etc/telemt-panel/config.toml`. Другой путь задаётся явно:

```sh
telemt-panel --config /etc/telemt-panel/config.toml
```

Ниже указаны значения загрузчика по умолчанию. Установщик может явно задать
другие значения в созданном файле, например выбрать SQLite вместо memory.

## Общие параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `listen` | `"0.0.0.0:8080"` | Адрес и порт HTTP/HTTPS-сервера панели. За локальным reverse proxy можно указать `"127.0.0.1:8080"`. |
| `base_path` | `""` | Префикс URL за reverse proxy, например `"/panel"`. |
| `trusted_proxies` | `[]` | Доверенные IP/CIDR reverse proxy. Только от них принимаются `X-Forwarded-For` и `X-Forwarded-Proto`. |
| `data_dir` | `"/var/lib/telemt-panel"` | Каталог состояния панели, временных файлов обновления и управляемых баз GeoIP. Нужен доступ на запись от пользователя панели. |

В `data_dir/panel-state.json` сохраняются настройки, сессии и параметры входа,
независимо от драйвера истории. При `data_dir = ""` это состояние живёт только
до завершения процесса. Каталог в `/tmp` также не переживает перезагрузку системы.
State-файл может содержать секреты; не публикуйте его и резервные копии.

### Reverse proxy

Прокси должен удалять `base_path` перед передачей запроса панели. Для
`base_path = "/panel"` пример nginx:

```nginx
location = /panel { return 301 /panel/; }
location /panel/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_buffering off;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

`base_path` допускает буквы ASCII, цифры и символы `._~/-`, без query-параметров.
Добавляйте в `trusted_proxies` только реальные адреса своего прокси, не весь интернет.

## `[tls]` — HTTPS самой панели

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `mode` | `http`, если TLS-ключи не заданы | `http` — без HTTPS; `certificate` — готовый сертификат; `acme` — встроенный Let's Encrypt. |
| `cert_file`, `key_file` | `""` | Пара PEM fullchain и приватного ключа для `certificate`; нужна доступность пользователю сервиса. Перечитываются при перезапуске. |
| `acme_domain` | `""` | Один домен для ACME: ASCII/punycode, без схемы, порта и wildcard. |
| `acme_cache_dir` | `<data_dir>/certs` | Постоянный каталог сертификатов и ACME account key; при пустом `data_dir` задаётся явно. Новый installer явно использует `/etc/telemt-panel/certs`, в том числе на OpenWrt. |

`mode` можно не указывать в старом формате: `acme_domain` выбирает ACME,
пара `cert_file`/`key_file` — готовый сертификат. Смешивать эти варианты нельзя.
Чтобы явно выключить HTTPS, задайте `mode = "http"` и удалите остальные TLS-ключи.
Это допустимый режим, но при публичном HTTP пароль, сессия и данные не шифруются;
passkey на обычном HTTP недоступен, за исключением поддерживаемых браузером
локальных development-контекстов. Ошибка ACME никогда не включает HTTP автоматически.

Раздел «Сервер → Настройки → Доступ к панели» меняет только `listen` и `[tls]`.
Проверка идёт до записи и сохраняет действующий listener; для ACME она может
сразу запросить сертификат и требует согласия с условиями Let's Encrypt.
Сохранение использует только нормализованный результат проверки, создаёт рядом
фиксированную резервную копию `.bak` и нормализует формат/комментарии TOML.
Сохранённая конфигурация и активный транспорт показываются раздельно: новый
адрес начинает работать только после отдельного перезапуска. Если стартовый
файл нельзя безопасно записать или управляемый перезапуск недоступен, панель
ничего не сохраняет и показывает доверенный путь к файлу и ручную команду.

Форма не меняет firewall, NAT, security groups, nginx/Caddy и `trusted_proxies`.
Смена публичного порта требует ручной проверки правил, а ACME — публичного
TCP/80. Успешные bind- и certificate-проверки не доказывают внешнюю доступность.
При смене домена сохраните вход по паролю: для нового origin может потребоваться
повторная авторизация и регистрация passkey.

Самостоятельная установка с ACME:

```toml
# Верхний уровень файла, до любых [разделов]
listen = "0.0.0.0:8443"

[tls]
mode = "acme"
acme_domain = "panel.example.com"
acme_cache_dir = "/etc/telemt-panel/certs"
```

Домен должен указывать на сервер; проверьте и A, и AAAA. Публичный TCP/80 должен
попадать на HTTP-01 listener панели при выпуске и последующих продлениях.
Основной HTTPS может использовать 8443, оставляя 443 для Telemt. Библиотека также
поддерживает TLS-ALPN-01, но свободный порт 443 не является условием HTTP-01.
Порт 80 не обслуживает интерфейс/API: только challenge и редирект на HTTPS.
Если обязательный listener не открылся, запуск завершается с ошибкой.

Выбор ACME означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/).
Выдача начинается при HTTPS-подключении; installer делает такой запрос сам.
Продление выполняет работающая панель, без acme.sh/cron и без своего перезапуска.
При сбое продления действующий сертификат сохраняется. Кеш не хранится в SQLite,
не очищается вместе с историей и должен переживать перезагрузку ОС; не используйте
для него `/tmp`. Не публикуйте кеш и его резервные копии.

Нестандартный `acme_cache_dir` (или `TP_TLS_CACHE_DIR` в installer) подготовьте
заранее: отдельный постоянный каталог с правами записи пользователю сервиса.
Установщик не меняет владельца произвольного внешнего каталога. В штатном
systemd unit `ProtectHome=true`: `/home`, `/root` и `/run/user` не подходят
для cache и файлов сертификата. Используйте, например, каталог внутри
`/etc/telemt-panel`; при собственной unit-конфигурации учитывайте её ограничения.

Для непривилегированного пользователя на systemd installer добавляет
`AmbientCapabilities=CAP_NET_BIND_SERVICE`, когда нужны низкие порты. В других
init-системах installer требует явно выбранный root для такого режима либо
ручную настройку подходящих прав сервиса; глобальные sysctl не меняет.

Проверка локального HTTPS после запуска:

```sh
telemt-panel tls check --config /etc/telemt-panel/config.toml --timeout 120s
```

Команда не открывает хранилище и не меняет конфиг; в режиме ACME проверяет
цепочку доверия и домен через SNI. Она может инициировать выдачу при первом TLS
подключении. В режиме `certificate` доверяет явно указанному сертификату:
успех этой проверки не означает, что браузеры доверяют вашей частной CA.
При отказе смотрите конкретный этап и ошибку в журнале сервиса; ошибка привязки
порта отличается от отказа CA или доступа к кешу. Локальная проверка не доказывает
доступность порта через внешний firewall.

## `[telemt]` — подключение к Telemt

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `url` | Обязателен | Базовый URL API Telemt, например `"http://127.0.0.1:9091"`. |
| `auth_header` | `""` | Полное значение заголовка `Authorization`, совпадающее с `server.api.auth_header` в Telemt. |
| `config_edit_mode` | `"api"` | Устаревший параметр совместимости с 0.x: значения `"api"` и `"file"` принимаются, но не выбирают способ редактирования. Для изменения настроек нужен Config API Telemt; прямая запись файла не поддерживается. |

## `[auth]` — вход в панель

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `username` | Обязателен | Логин администратора. В примере — `"admin"`. |
| `password_hash` | Обязателен | Bcrypt-хеш пароля, не пароль открытым текстом. |
| `session_ttl` | `"720h"` | Скользящий срок сессии. Положительная длительность, например `"24h"` или `"720h"`; суффикс `d` не поддерживается. |

Хеш создаётся интерактивно, без пароля в аргументах командной строки:

```sh
telemt-panel hash-password
```

Изменение логина или хеша завершает прежние сессии при следующем запуске.
Порядок сброса пароля: [восстановление доступа](ACCESS_RECOVERY.md).

## `[store]` — хранение истории

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `driver` | `"memory"` | `"sqlite"` — история на диске; `"memory"` — история в RAM, исчезающая при перезапуске. |
| `path` | `""` | Путь к SQLite-файлу. Обязателен для `"sqlite"`, не используется для `"memory"`. |

Для сервера обычно используется:

```toml
[store]
driver = "sqlite"
path = "/var/lib/telemt-panel/panel.db"
```

Обычная сборка поддерживает оба драйвера, lite — только memory. Переключение
драйвера или пути не переносит старую историю автоматически. `data_dir` и
`store.path` независимы: смена каталога состояния не меняет путь базы.

Если при запуске SQLite недоступна или повреждена, панель использует временную
историю в памяти и показывает предупреждение. После устранения причины нужен
перезапуск; временная история автоматически в SQLite не переносится.
Ошибки конфигурации, несовместимая схема базы и отсутствие SQLite в lite остаются
фатальными. CLI `store export/import` не подменяет недоступную базу памятью.

Политики хранения, GeoIP и дополнительные способы входа сохраняются отдельно
в state-файле; TOML-параметров для них нет.

## `[subpage]` — страницы подписки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `enabled` | `false` | Включает страницы `/sub/<token>`, доступные без входа администратора. |
| `secret` | `""` | HMAC-ключ токенов. Обязателен при включении; установщик генерирует его автоматически. |

## `[host]` — сервисы и журналы

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `service_manager` | `"auto"` | `auto`, `systemd`, `openrc`, `procd`, `sysvinit`, `docker` или `none`. |
| `log_source` | `"auto"` | `auto`, `journald`, `logread`, `syslog`, `docker` или `file`. |
| `log_file` | `""` | Путь к журналу при `log_source = "file"`. |
| `telemt_service` | `"telemt"` | Имя службы Telemt. |
| `panel_service` | `"telemt-panel"` | Имя службы панели. |
| `telemt_container` | `"telemt"` | Имя контейнера Telemt при работе через Docker. |
| `panel_container` | `"telemt-panel"` | Имя контейнера панели при работе через Docker. |

`auto` определяет доступные средства при запуске. Имена служб и контейнеров
должны соответствовать установленным на вашем сервере.

При потоковом чтении `file`/`syslog` панель сохраняет первые 256 КиБ каждой
строки и выдаёт её после перевода строки. Превышение отмечается
` [line truncated after 262144 bytes]`; исходный файл не меняется.
Для таких строк фильтр `syslog` ищет имя службы только в сохранённом префиксе.

## `[privileges]` — права на операции с хостом

`mode = "auto"` выбирает прямое выполнение под root, иначе доступный
неинтерактивный sudo, иначе ручные команды. Можно явно указать `"direct"`,
`"sudo"` или `"manual"`. Выбранный режим используется и для Telemt, и для панели;
сам параметр не выдаёт процессу дополнительных прав.

## `[updates]` — обновления

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `telemt_repo` | `"telemt/telemt"` | GitHub-репозиторий релизов Telemt в формате `owner/name`. |
| `panel_repo` | `"amirotin/telemt_panel"` | GitHub-репозиторий релизов панели. |
| `github_token` | `""` | Необязательный токен GitHub для приватного репозитория или повышения лимита API. |
| `telemt_binary_path` | `"/bin/telemt"` | Установленный бинарник Telemt, заменяемый при обновлении. |
| `panel_binary_path` | `"/usr/local/bin/telemt-panel"` | Установленный бинарник панели, заменяемый при обновлении. |

Пути должны совпадать с фактическими исполняемыми файлами служб.
Конфигурацию с токенами храните с ограниченными правами чтения.
