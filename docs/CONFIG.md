# Конфигурация панели

Этот документ описывает **TOML-файл самой Telemt Panel 1.x**, а не конфиг Telemt.
Параметры Telemt редактируются отдельно, через его Config API.

Полный пример — [config.example.toml](../config.example.toml). Установщик создаёт
`/etc/telemt-panel/config.toml`; при ручном запуске по умолчанию читается
`config.toml` из рабочего каталога:

```sh
telemt-panel --config /etc/telemt-panel/config.toml
```

После ручных изменений нужен перезапуск панели. Обычные настройки интерфейса
хранятся в `panel-state.json` и не переписывают TOML. Исключение — явно
подтверждённая настройка доступа: она меняет адрес, путь и TLS выбранного входа
(панели либо подписки), сохраняя остальные параметры.

В таблицах ниже — **значения загрузчика**, а не ответы установщика. Например,
загрузчик выбирает историю в memory, установщик на обычном сервере — SQLite.

## Минимальный пример

Сначала создайте хеш пароля интерактивной командой:

```sh
telemt-panel hash-password
```

Замените заглушку в примере на полученный bcrypt-хеш:

```toml
listen = "127.0.0.1:8080"
data_dir = "/var/lib/telemt-panel"

[telemt]
url = "http://127.0.0.1:9091"
auth_header = ""

[auth]
username = "admin"
password_hash = "REPLACE_WITH_BCRYPT_HASH"

[store]
driver = "sqlite"
path = "/var/lib/telemt-panel/panel.db"
```

Этот вариант доступен только локально: используйте SSH-туннель или reverse proxy.
Для lite замените `[store]` на `driver = "memory"` и уберите `path`.

## Проверка и безопасность файла

```sh
telemt-panel config check --config /etc/telemt-panel/config.toml
telemt-panel config inspect --config /etc/telemt-panel/config.toml
```

`check` проверяет структуру и параметры; `inspect` выдаёт JSON-сводку без паролей,
хешей и токенов. Команды не запускают сервисы, не записывают состояние и не
проверяют доступность Telemt, права на каталоги или сертификаты. Вход — обычный
файл не более 1 МиБ. Неизвестные ключи и смешение схем 0.6/1.x отклоняются.

Формат определяется автоматически; `--format current` или `--format 0.6` задаёт
его явно. Старый TOML 0.6.2 поддерживается без автоматической перезаписи.
Перенос состояния и явный экспорт текущей схемы описаны в [обновлении](UPGRADING.md).

Храните файл с правами `0600`, владельцем должен быть пользователь службы.
Не публикуйте конфиг, `panel-state.json`, TLS-ключи и их резервные копии.
Для путей рекомендуется абсолютная запись: относительные пути разрешаются
от рабочего каталога процесса, **не от каталога config.toml**.

## Общие параметры

Эти ключи записываются в начале файла, **до первого `[раздела]`**.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `listen` | `"0.0.0.0:8080"` | Адрес HTTP/HTTPS listener: `host:port`, порт 1–65535. За локальным прокси — `"127.0.0.1:8080"`; IPv6 записывается как `"[::]:8080"`. |
| `base_path` | `""` | Префикс URL, например `"/panel"`. Допустимы ASCII-буквы, цифры и `._~/-`; без query/fragment. Завершающий `/` нормализуется. |
| `public_url` | `""` | Внешний HTTP(S)-адрес панели. Полный URL с путём допустим, если путь совпадает с `base_path`; query, fragment и credentials запрещены. |
| `trusted_proxies` | `[]` | IP/CIDR ваших reverse proxy. Только от них принимаются `X-Forwarded-For` и `X-Forwarded-Proto`. Пусто — заголовкам не доверяем. |
| `data_dir` | `"/var/lib/telemt-panel"` | Каталог `panel-state.json`, staging обновлений и управляемых GeoIP-баз. Пользователю службы нужны права записи. |

`data_dir = ""` делает настройки и сессии временными, до завершения процесса.
Каталог в `/tmp` также не переживает перезагрузку ОС. На OpenWrt установщик
по умолчанию использует `/tmp/telemt-panel`; для постоянного состояния нужен
отдельно выбранный постоянный каталог. Драйвер истории этого не меняет.

## `[telemt]` — подключение к Telemt

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `url` | Обязателен | Базовый URL API Telemt, например `"http://127.0.0.1:9091"`. |
| `auth_header` | `""` | Полное значение `Authorization`, соответствующее `server.api.auth_header` в Telemt. Панель отправляет его без добавления префикса. |
| `config_edit_mode` | `"api"` | Устаревший ключ совместимости: `api` и `file` принимаются, но редактирование всегда требует Config API. Прямой записи конфига Telemt нет. |

Не открывайте API Telemt в интернет ради панели. При совместной установке
достаточно loopback; порт панели и порт API Telemt — разные listener.

## `[auth]` — вход администратора

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `username` | Обязателен | Логин единственного администратора панели. |
| `password_hash` | Обязателен | Bcrypt-хеш, созданный `telemt-panel hash-password`. В текущем формате открытый пароль не принимается. |
| `session_ttl` | `"720h"` | Скользящий срок сессии: положительная длительность, например `"24h"` или `"720h"`. Суффикс `d` не поддерживается. |

Изменение логина или хеша отзывает прежние сессии при следующем запуске.
Passkeys настраиваются отдельно и сохраняются в state-файле, не в TOML.
Для них нужен HTTPS, кроме разрешённого браузером localhost-контекста.
Если доступ потерян — [восстановление доступа](ACCESS_RECOVERY.md).

## `[store]` — история наблюдений

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `driver` | `"memory"` | `sqlite` — история на диске, `memory` — в RAM до перезапуска. |
| `path` | `""` | SQLite-файл; обязателен для sqlite, не используется для memory. |

Full поддерживает оба драйвера, lite — только memory. Сессии, passkeys и настройки
панели хранятся отдельно в `data_dir/panel-state.json`. Политики хранения и GeoIP
настраиваются в интерфейсе: TOML-ключей для них нет.

`store.path` и `data_dir` независимы. Смена драйвера или пути не переносит историю.
При недоступной SQLite панель запускается с временной историей и предупреждением;
после устранения причины нужен перезапуск. Временная история не переносится
автоматически. Неверный конфиг, несовместимая схема БД и sqlite в lite остаются
ошибками запуска. Команды `store export/import` не подменяют БД памятью.

## `[subpage]` — пользовательские ссылки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `enabled` | `false` | Включает отдельный listener клиентских страниц без входа администратора. |
| `secret` | `""` | HMAC-ключ ссылок, обязателен при включении. Установщик генерирует его автоматически. |

Используйте длинный случайный ключ, например 32 случайных байта в hex-виде.
Смена ключа делает ранее выданные ссылки недействительными. Ссылку пользователя
следует считать секретом доступа, а не публичной страницей.

Подписка слушает отдельный порт; API и вход администратора там недоступны.
Адрес ссылки — `public_url + base_path + /<token>`. Без `public_url` используется
имя хоста обращения к панели (либо домен ACME подписки) и порт подписки;
это не проверка доступности из Интернета. Для туннеля или reverse proxy задайте
внешний адрес явно. Выключенная подписка не занимает порт.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `listen` | `"127.0.0.1:8081"` | Собственный адрес и порт подписки, отличный от порта панели. |
| `base_path` | `"/sub"` | Непустой строгий префикс: можно заменить `/sub` собственным путём. |
| `public_url` | `""` | Внешний HTTP(S)-адрес, например `https://links.example.com`. |
| `tls` | `[subpage.tls]` | Независимый транспорт; те же параметры, что в `[tls]`, по умолчанию HTTP. |

Для ACME двух адресов используется один общий HTTP-01 listener на TCP/80.
При одинаковом домене укажите одинаковый `acme_cache_dir`: сертификат и его
продление переиспользуются. Разные домены по умолчанию используют отдельные кеши
(подписка — `data_dir/certs/subscription`). Сертификат выпускается для домена,
а не порта. Ошибки TLS не приводят к автоматическому переходу на HTTP.
Если порт 80 занят nginx/Caddy, выберите HTTPS через него или готовые PEM-файлы.

Управление адресами доступно в настройках панели. Сохранение меняет TOML, но
применение требует перезапуска. При ручном запуске перезапустите процесс сами.
Первое включение через форму создаёт ключ подписи, если его ещё нет; выключение
и повторное включение ключ не меняют. Смена пути/внешнего адреса меняет URL.

## `[tls]` — транспорт панели

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `mode` | `http`, если TLS-ключей нет | `http`, `certificate` или `acme`. |
| `cert_file` | `""` | PEM-сертификат/fullchain для certificate. |
| `key_file` | `""` | PEM-приватный ключ для certificate. |
| `acme_domain` | `""` | Один DNS-домен для ACME: без схемы, порта и wildcard; ASCII/punycode. |
| `acme_cache_dir` | `<data_dir>/certs` | Постоянный каталог ACME account key и сертификатов. При пустом data_dir задаётся явно. |

Если `mode` пропущен, домен выбирает acme, а пара cert/key — certificate.
Смешивать параметры разных режимов нельзя. При `mode = "http"` удалите остальные
TLS-ключи. Ошибка ACME не переключает панель на HTTP. На публичном HTTP пароль
и сессия передаются без шифрования.

### Встроенный ACME

Измените верхнеуровневый `listen` и секцию `[tls]` в полном конфиге:

```toml
listen = "0.0.0.0:8443"

[tls]
mode = "acme"
acme_domain = "panel.example.com"
acme_cache_dir = "/etc/telemt-panel/certs"
```

DNS A/AAAA должны вести на сервер, публичный TCP/80 — на HTTP-01 listener панели
при выпуске и продлении. Основной HTTPS может работать на 8443, оставляя 443 для
Telemt. Порт 80 обслуживает challenge и редирект, а не интерфейс/API.

ACME работает внутри бинарника, без acme.sh/cron; продление не требует рестарта.
Выдача начинается при HTTPS-подключении, а установщик делает проверочный запрос.
Выбор ACME означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/).
При ошибке продления действующий сертификат сохраняется.

Кеш должен переживать перезагрузку; не используйте `/tmp`. Новый установщик
выбирает `/etc/telemt-panel/certs`. Внешний каталог подготовьте самостоятельно
с правами записи пользователя службы. Штатный systemd unit скрывает `/home`,
`/root` и `/run/user` через `ProtectHome=true` — не размещайте там ключи и кеш.

Для портов ниже 1024 нужны соответствующие права. Установщик на systemd выдаёт
службе `CAP_NET_BIND_SERVICE`, когда это нужно; другие init-системы требуют root
для такого режима либо собственной настройки прав.

### Готовый сертификат

```toml
[tls]
mode = "certificate"
cert_file = "/etc/telemt-panel/fullchain.pem"
key_file = "/etc/telemt-panel/privkey.pem"
```

Оба файла должны читаться пользователем службы. После их замены перезапустите
панель. Для проверки работающего HTTPS:

```sh
telemt-panel tls check --config /etc/telemt-panel/config.toml --timeout 120s
```

В certificate-режиме команда доверяет указанному сертификату; это не доказывает
доверие браузера к вашей CA. В ACME проверяются цепочка и домен через SNI;
первое подключение может инициировать выдачу сертификата.

### За nginx или Caddy

В панели используйте `listen = "127.0.0.1:8080"`, `base_path = "/panel"`,
`trusted_proxies = ["127.0.0.1/32"]` и `[tls] mode = "http"`.
Внешний HTTPS обслуживает прокси, внутренний HTTP остаётся на loopback.

nginx, внутри HTTPS server:

```nginx
location = /panel { return 301 /panel/; }
location /panel/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_buffering off;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Caddy:

```caddyfile
panel.example.com {
    redir /panel /panel/ 308
    handle /panel/* {
        reverse_proxy 127.0.0.1:8080
    }
}
```

Оба примера сохраняют префикс — это обязательно. Вне настроенного префикса
панель возвращает 404 без перенаправления. Не используйте Caddy `handle_path`
или завершающий `/` в nginx `proxy_pass`, удаляющие префикс.
Путь не заменяет авторизацию панели или персональный токен подписки.

Пример независимой подписки за Caddy:

```toml
[subpage]
enabled = true
listen = "127.0.0.1:8081"
base_path = "/access-m4p2"
public_url = "https://links.example.com"
secret = "REPLACE_WITH_A_LONG_RANDOM_SECRET"

[subpage.tls]
mode = "http"
```

```caddyfile
links.example.com {
    handle /access-m4p2/* {
        reverse_proxy 127.0.0.1:8081
    }
    respond 404
}
```

Клиент получит `https://links.example.com/access-m4p2/<token>`. Внутренний HTTP
на loopback здесь не означает публичный HTTP: внешний HTTPS обеспечивает Caddy.

Caddy сам выставляет forwarded-заголовки и передаёт SSE без дополнительных
настроек буферизации. [Документация reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).

## `[host]` — службы и журналы

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `service_manager` | `"auto"` | `auto`, `systemd`, `openrc`, `procd`, `sysvinit`, `docker`, `none`. |
| `log_source` | `"auto"` | `auto`, `journald`, `logread`, `syslog`, `docker`, `file`. |
| `log_file` | `""` | Путь при log_source=file. |
| `telemt_service` | `"telemt"` | Имя службы Telemt. |
| `panel_service` | `"telemt-panel"` | Имя службы панели. |
| `telemt_container` | `"telemt"` | Имя контейнера Telemt при Docker-управлении/логах. |
| `panel_container` | `"telemt-panel"` | Имя контейнера панели при Docker-управлении/логах. |

`auto` определяет доступные средства при запуске. `none` отключает управляемые
операции со службами. Docker-режим требует доступного Docker CLI и соответствующих
прав; установщик не создаёт контейнеры и не настраивает этот доступ автоматически.

## `[privileges]` — права на операции

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `mode` | `"auto"` | `auto`, `direct`, `sudo`, `manual`. |

`auto`: прямое выполнение под root → доступный неинтерактивный sudo → ручные
команды. Режим общий для Telemt и панели. `direct` не выдаёт процессу права root,
а `sudo` не создаёт политику разрешений. `manual` показывает команды для
самостоятельного выполнения. Отдельного агента нет.

## `[updates]` — источники и пути обновлений

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `telemt_repo` | `"telemt/telemt"` | GitHub-репозиторий Telemt, owner/name. |
| `panel_repo` | `"amirotin/telemt_panel"` | GitHub-репозиторий панели. |
| `github_token` | `""` | Необязательный токен для приватных репозиториев или увеличения лимита API. |
| `telemt_binary_path` | `"/bin/telemt"` | Бинарник Telemt, заменяемый при обновлении. |
| `panel_binary_path` | `"/usr/local/bin/telemt-panel"` | Бинарник панели, заменяемый при обновлении. |

Пути и имена `[host]` должны совпадать с фактическими unit/init-скриптами и sudoers.
Их изменение в TOML не перенастраивает систему. Проверка версий, режим
автообновления и интервал сохраняются в state-файле, не в этой секции.

Обновление существующей установки не переписывает config/unit/sudoers.
Порядок обновления и отката — в [UPGRADING.md](UPGRADING.md).
