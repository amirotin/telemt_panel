# Конфигурация хранилища

Обычная сборка `telemt-panel` — full и включает memory, SQLite, PostgreSQL и MySQL/MariaDB. `telemt-panel-lite` предназначена для роутеров и включает только memory. Текущий вариант и список драйверов показывает `telemt-panel version` и `GET /api/health`.

## SQLite

Рекомендуемый вариант для одной панели на сервере:

```toml
[store]
driver = "sqlite"
path = "/var/lib/telemt-panel/panel.db"
```

## PostgreSQL

```toml
[store]
driver = "postgres"
dsn = "postgres://telemt_panel:password@127.0.0.1:5432/telemt_panel?sslmode=require"
```

Проверка до изменения конфига:

```sh
telemt-panel store check --driver postgres --dsn 'postgres://…'
```

## MySQL / MariaDB

```toml
[store]
driver = "mysql"
dsn = "telemt_panel:password@tcp(127.0.0.1:3306)/telemt_panel?parseTime=true"
```

```sh
telemt-panel store check --driver mysql --dsn 'telemt_panel:…'
```

Конфиг содержит секрет подключения и должен быть доступен только владельцу (`0600`). Панель не выводит DSN в лог, API или интерфейс.

Если PostgreSQL/MySQL недоступна при старте, панель запускается с временным memory-store. Управление Telemt и живые данные продолжают работать, но временные сессии, настройки и история теряются при перезапуске. Панель не подключается к базе на лету и не переносит туда накопленные данные: после восстановления БД требуется перезапуск.

## Что хранится

Техническая история обязательна: она нужна для графиков состояния панели и хранится в ограниченных временных рядах. Остальные категории включаются администратором отдельно в разделе «Сервер → Хранилище». По умолчанию персональная история трафика отключена.

История трафика пользователя сохраняет только объём за интервал: без IP-адресов, маршрутов и сырых снимков пользователя. Нулевые интервалы не записываются. За последние 24 часа используются 15-минутные корзины, более старая часть выбранного периода представлена часовыми корзинами. При удалении пользователя его персональная история также удаляется.

Лента событий хранит структурированные переходы состояния и безопасные административные действия для сопоставления с графиками. В неё не копируются сырые логи, адреса клиентов, секреты, полные конфиги и данные входа администратора. API явно различает отключённую историю, пустой период, частичную ретенцию и временно недоступный источник — пустой график не выдаётся за нулевую активность.

## Memory

```toml
[store]
driver = "memory"
```

Этот режим подходит OpenWrt и временным установкам. История остаётся в RAM. Обязательное состояние панели всегда отделено от истории и при заданном `data_dir` сохраняется в `data_dir/panel-state.json`: сессии, настройки, политики, TOTP/passkeys, nonce, аудит и recovery-журнал обновлений.

## Резервная копия и перенос истории

Остановите панель, выгрузите состояние из текущего драйвера, затем укажите в отдельной копии конфига новый драйвер и пустую базу:

```sh
telemt-panel store export --config /etc/telemt-panel/config.toml --out panel-store.json
telemt-panel store import --config /etc/telemt-panel/config-new.toml --in panel-store.json
```

Экспорт объединяет локальное состояние панели и историю выбранного драйвера в один переносимый файл, но сохраняет их как независимые части. Он включает сессии, настройки, nonce, recovery-журнал, политики, ограниченный аудит, auth-состояние, метрики и события; незавершённые WebAuthn-операции, DSN и параметры конфига не экспортируются. Файл содержит чувствительные данные авторизации, создаётся с правами `0600`, а существующий файл команда не перезаписывает. При импорте state-часть возвращается в `panel-state.json`, а метрики и события — в пустое хранилище истории.

## Переключение варианта бинаря

Вариант меняется только установщиком, без перезаписи существующего конфига:

```sh
sh install.sh --variant full
sh install.sh --variant lite
```

Lite не может открыть SQLite/PostgreSQL/MySQL. При обновлении существующей установки установщик проверяет сохранённый конфиг до замены бинарника и откажется переключать такой профиль на lite. Для осознанного перехода сначала перенесите нужное состояние и смените драйвер на memory.
