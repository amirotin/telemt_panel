# Entware и нестандартные службы

Панель поддерживает пользовательские команды управления без зависимости от
systemd. Для Entware обычные команды — `/opt/etc/init.d/S99telemt restart` и
`/opt/etc/init.d/S99telemt-panel restart`, но имена могут отличаться.

## Требования

- Совместимый бинарник панели: текущие сборки — `aarch64` и `x86_64`.
  Наличие Entware не означает совместимость с ARMv7/MIPS: таких сборок сейчас нет.
- Работающий Telemt с доступным API.
- Исполняемые скрипты, управляющие именно своим экземпляром программы и
  возвращающие ненулевой код при ошибке.
- Права на эти команды и на замену бинарников, если нужны обновления из панели.

## Новая установка

Установщик распознаёт Entware по характерным файлам `rc.unslung` и `opkg`, а не
по одному наличию пакетного менеджера. Для этой среды используются:

| Назначение | Путь по умолчанию |
| --- | --- |
| Бинарник панели | `/opt/bin/telemt-panel` |
| Конфиг панели | `/opt/etc/telemt-panel/config.toml` |
| Техническое состояние и история | `/opt/var/lib/telemt-panel` |
| Скрипт панели | `/opt/etc/init.d/S99telemt-panel` |
| Журнал самой панели | `/opt/var/log/telemt-panel.log` |

Автозапуск опирается на уже настроенный запуск Entware при загрузке устройства.
Установщик не меняет загрузочные настройки прошивки. Скрипт панели привязывает
PID к исполняемому файлу и конкретному конфигу; существующий скрипт с тем же
именем автоматически не перезаписывается.

Панель устанавливается для запуска от root с `privileges.mode = "direct"`.
Отдельная копия бинарника для privileged helper и root policy не создаются;
обновление выполняет сама панель с уже имеющимися правами.

## Уже установленная панель

1. Проверьте реальные пути бинарников и скриптов. В Entware они находятся под
   `/opt`, но самописная установка может отличаться.
2. Для конфига 0.x сначала выполните [переход на формат 1.x](UPGRADING.md).
   Не добавляйте новые таблицы к старому формату без преобразования.
3. Добавьте в конфиг панели [все четыре пользовательские команды](CONFIG.md#hostcommands--пользовательские-команды),
   подставив свои пути. Это настройка **панели**, не `telemt.toml`.
4. Проверьте `updates.telemt_binary_path` и `updates.panel_binary_path`:
   команды перезапуска не заменяют настройку путей обновления.
5. Перезапустите панель своим скриптом. В разделе «Платформа» должен отображаться
   менеджер «Пользовательские команды».

Например, бинарники могут находиться в `/opt/bin/telemt` и `/opt/bin/telemt-panel`.
Если Telemt установлен как `/opt/bin/telemt/telemt`, укажите именно этот путь.
Не перемещайте существующие файлы только ради совпадения с примером.

Если в существующей Entware-установке ещё не настроен `custom`, установщик
останавливает обновление до замены бинарника и показывает необходимые параметры.
Добавьте команды и повторите операцию. Уже заданные команды и самописные скрипты
при обычном обновлении не переписываются. Автоматическое удаление самописного
скрипта, которым установщик не управляет, не выполняется.

При запуске от root режим `privileges.mode = "auto"` использует прямое выполнение.
Для отдельного пользователя нужны точные разрешения sudo на настроенные команды
и операции обновления. Если их нет, используйте ручной режим; не выдавайте
`NOPASSWD: ALL` и не разрешайте произвольные shell-команды.

Журнал панели — не журнал Telemt. В новой Entware-установке источник журнала
Telemt оставлен неподключённым (`host.log_source = "file"`, `host.log_file = ""`).
Для его включения укажите реальный путь к файлу, в который пишет **Telemt**;
у самописных скриптов этот путь может отличаться. Не подставляйте туда
`telemt-panel.log`.

## Что означает статус

В пользовательском режиме панель не предполагает наличие команды `status` и не
выводит состояние службы из доступности API. Поэтому «Статус неизвестен» здесь
ожидаем: запуск, остановка и перезапуск доступны с подтверждением при наличии прав.
Успех команды означает её успешное завершение, а не доказательство готовности API.

Не используйте `rc.unslung restart` для кнопки Telemt: такая команда управляет
всем набором служб Entware. Команды должны относиться к конкретной программе.
Панель не определяет по содержимому самописного скрипта, что именно он остановит.

Скрипт перезапуска панели должен продолжать работу после завершения вызывающей
его панели. В частности, его вывод не должен зависеть от закрывающихся stdout/stderr
старого процесса. Сгенерированный установщиком скрипт направляет вывод перезапуска
в журнал заранее; для самописного скрипта это необходимо проверить отдельно.

## Безопасная проверка

Сначала проверьте команды вручную в подходящее время: остановка/перезапуск
Telemt разрывает соединения клиентов. Затем проверьте управление из панели,
сохранение технического state-файла после перезапуска и автозапуск после
перезагрузки роутера. Обновление проверяйте с резервной копией и доступом по SSH.

Для самостоятельного запуска настроенной команды перезапуска панели есть CLI:

```sh
/opt/bin/telemt-panel service restart --target panel --config /opt/etc/telemt-panel/config.toml
```

Он не запускает веб-сервер или фоновые сборщики и выполняет команду с правами
вызвавшего пользователя. Сам по себе CLI не предоставляет повышенные права.

Проверки на изолированной раскладке `/opt` не заменяют проверку на самом роутере:
важны ядро, набор утилит и поведение конкретных управляющих скриптов.
